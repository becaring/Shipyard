# Shared optimization evidence

Consumers remain pinned to `58d4344`; this branch is a separate adoption candidate.

## JSON vector conversion

- Owner: `sources/json/include/nlohmann/json.hpp`, `detail::conversion<std::vector<T, A>>::get`; ordered JSON is regenerated by the existing backend projector.
- Selected users: both consumers compile `sources/json/json.cpp`. Their projected `Config::GetArray` calls this conversion; Modern's selected network `AllClientState` also converts its client array on connection-state updates. This is configuration/network-event work, not an established frame bottleneck. Header references are outside the relationship index's direct coverage.
- The destination's final element count is already available. Reserve once before copying elements instead of repeatedly growing and relocating the vector. The destination owns its storage, does not alias the input, and preserves conversion order and type checks; no persistent cache or invalidation is introduced.
- Actual ordinary/ordered conversion tests cover 0/1/64/1024 entries, values/order, ownership after source destruction, invalid types/elements, allocation failure, and cleanup. A 64-element host conversion previously allocated destination storage 12 times; now it allocates once. Empty conversion allocates zero times.
- Host contracts and affected PowerPC source/contract compilation pass. Ordered generated output contains the reviewed reservation. No target runtime timing or FPS measurement was performed.
- The pinned [nlohmann 3.12.0 conversion](https://github.com/nlohmann/json/blob/55f93686c01528224f448c19128836e7df245f72/include/nlohmann/detail/conversions/from_json.hpp#L256-L277) already reserves before converting elements. This restores that lost efficiency and its allocation-failure ordering; an additional regression covers allocation failure with an invalid first element.

## Empty and singleton normal batches

- Owner: `sources/fast3d/normal_sources.h`, `BatchNormalSources`. Smash's selected `Libultraship360-release` interpreter calls it from `GfxSpVertex` through `tools/vertex_reuse_projection.py`, under the existing lighting, bounds, and source-disjointness guards. Several command count fields can represent one vertex. No selected Modern caller was established.
- A singleton can only select its own normal. Preserve the existing invalid-input/count checks, then return index zero without reading the normal or initializing the 64-entry hash table. Empty calls preserve their untouched output. Larger batches retain the existing collision/reuse algorithm.
- Test-only instrumentation of the actual header proves 64 initializations to zero and one normal-record read to zero for a singleton. It covers all 256 byte values, output bounds, null/count rejection, collisions, and the 256-entry limit. A three-entry call still performs 64 initializations and three record reads. Production has no counters.
- Native PPC disassembly confirms the new early return precedes the 64-store loop and normal loads; the old compiled helper always enters that initialization loop. Larger batches incur an additional compare/branch. Evidence is saved under `scratch/normal-sources-proof`; singleton frequency and net target runtime benefit remain unmeasured.
